# 从看见效果，到说清需求

你不必先学会编程，才能描述自己想要的界面。先说清看见的结构和希望发生的变化，再认识对应的专业叫法，最后把它们组织成具体需求。

## 先看见效果 {#see}

先想一个具体动作：点击后菜单出现、选中后内容更新，或按下关闭按钮后弹窗消失。把触发动作和前后变化讲清楚，比只说“做一个好看的下拉框”更容易得到符合预期的实现。

## 再认识专业名称 {#name}

给界面效果找到更准确的词汇：例如下拉选择常称为 **Dropdown**，从页面侧边滑出的面板常称为 **Drawer**。知道这些名称后，可以更准确地检索资料，也能减少和 AI 沟通时的歧义。组件词典按操作、输入、导航、布局、反馈等类别整理常见条目。

## 把想法说清楚 {#prompt}

描述一个界面时，可以说明：

1. **组件**：要做下拉框、抽屉，还是其他效果？
2. **触发方式**：点击、悬停，还是键盘操作？
3. **状态变化**：打开后显示什么，选中后发生什么？
4. **边界细节**：怎样关闭，手机上如何呈现？

例如：“做一个下拉选择器，默认显示当前选项；点击后展开选项列表；选择一项后关闭列表并更新显示；点击外部或按 Escape 时关闭。”这类描述把组件、外观、触发方式和状态变化放在一起，能帮助 AI 更准确地实现需求。提示词仍需按你的页面和设计调整，不是复制后就能适用所有项目的成品代码。

## 词典目前包含什么

组件词典按 11 类整理了 188 个界面组件与交互条目。基础操作中的按钮栏目已开放 10 个独立文档，提供 49 种可交互样例、适用场景和中文提示词；其他分类目前提供条目名称与概念入口，相关示例内容会逐步完善。工程术语的可视化演示也会逐步增加，并区分演示模型与真实生产系统。
