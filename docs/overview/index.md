# 从看见效果，到说清需求

你不必先学会编程，才能描述自己想要的界面。先试用一个效果，再认识它的专业叫法，最后把这些信息组合成清楚的需求。

## 先看见效果 {#see}

从下拉框、侧边抽屉、弹窗、标签页等常见交互开始。通过点击和切换，观察界面在不同状态下怎样变化。

## 再认识专业名称 {#name}

给看见的东西找到准确词汇：例如下拉选择叫 **Dropdown**，从页面侧边滑出的面板叫 **Drawer**。掌握叫法后，更容易搜索示例，也能减少和 AI 沟通时的歧义。

## 把想法说清楚 {#prompt}

描述一个界面时，可以说明：

1. **组件**：要做下拉框、抽屉，还是其他效果？
2. **触发方式**：点击、悬停，还是键盘操作？
3. **状态变化**：打开后显示什么，选中后发生什么？
4. **边界细节**：怎样关闭，手机上如何呈现？

把这些条件写进提示词，AI 更容易做出接近预期的结果。提示词仍需要按你的页面和设计调整，不是复制后就能适用于所有项目的成品代码。

## 内容会怎样展开

首期从前端效果出发，逐步补充可操作的示例和表达方式。之后再用流程或小型模拟解释幂等、分布式等工程术语，并标明演示模型与真实生产系统的区别。
